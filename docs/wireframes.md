- 任务：T-003；负责会话：S-002；版本：线框 v0.4，2026-10-29（同步详情与子表空态文案）。
- 依据：[需求 v0.11](requirements.md)第 1–8 节及第 9 节验收、[技术方向](technical-direction.md)第 3 节。
- 状态：用户于 2026-10-28 认可先按本稿实现，后续发现问题再调整；本页 D01–D13 作为当前实现默认值，R 编号沿用已确认需求。

## 1. 先看线框

打开[交互线框](design/wireframes.html)。左侧为桌面组件，右侧为 App 承载页面；侧边场景入口覆盖完整流程。点击组件或 App 中的任务、按钮可继续操作。用“重置演示数据”恢复样例。

2026-10-29 实测修订：用户认可当前 4×4 组件尺寸，并要求保留拖动边框调整大小。沿用同一种布局，伸缩优先改变列表高度；HTML 与原 PNG 展示结构和交互，实际默认尺寸以 P60 组件及 R64 为准。

同日追加反馈：App 页面统一黑色背景，子表菜单仅保留顶部返回入口；完成、恢复、取消日期及删除等确认只显示居中弹窗，背景保留原桌面或 App 页面。D01、D06、D07、D13 同步修订，交互 HTML 与 App 总览已更新。

快速对照：[三个组件视图](design/widget-views.png)｜[App 页面总览](design/app-pages.png)。

线框为独立 HTML，无外部依赖，可双击在浏览器打开。网页 Escape 模拟 Android 返回，界面左上角也提供返回按钮。演示时间固定为 **2026-10-28 10:00**，用来稳定呈现过期效果；演示数据仅保存在网页内存中，刷新重置。

建议审阅顺序：三个视图 → 添加/详情 → 日期 → 排序 → 表管理 → 确认 → 空态。桌面与 App 两侧共用样例任务，分别保留自己的表与子表选择。组件发起的流程结束后，右侧显示“已返回桌面”；这表示 Android 返回行为的设计目标。

本稿用于确定布局和行为。设备实测、Android 生命周期、桌面宿主效果和持久化验收由 T-004 及后续工程任务完成。

## 2. 桌面组件

### 2.1 固定区与滚动区

从上到下为：

1. 表标签行：左翻页、最多三个表标签、右翻页；当前表用白色底线区分。
2. 子表与操作行：有日期、无日期、已完成；右侧添加 `+` 和子表菜单 `…`。
3. 任务列表：仅此区域纵向滚动；行内标题与日期均为单行。

组件底色 `#000000`；标题白色；过期且未完成的标题暂用 `#FF8585`，日期暂用 `#FFB366`。选中状态同时通过底线和字重体现。状态色遵循 R16、R17、R31、R32，色值属于 D01 默认值。

网页外壳中的系统栏、桌面文字、底部图标与手势条用于说明边界，不属于组件内容。布局按约 360dp 宽的可用区域起稿，手机 1220 × 2700 像素不直接换算为逻辑尺寸。组件实际可用宽高、系统边距与圆角由 T-004 测量。

### 2.2 三种行布局

| 视图 | 从左至右 | 顺序与状态 |
|---|---|---|
| 有日期 | 未勾选框 → 弹性标题 → `YYYY-MM-DD` → `×` | 日期升序；同日有时分升序，随后无时分；完全同一时刻新创建在前；过期标题红色 |
| 无日期 | 未勾选框 → 弹性标题 → `×` | 保存的人工顺序；新增、取消日期和无日期恢复置顶 |
| 已完成 | 已勾选框 → 弹性标题 → `×` | 最新完成在前；标题始终白色；隐藏日期与添加 `+` |

同日定时任务即使组件仅显示年月日，仍按完整时分排序；点标题查看完整日期。完成的过期任务也保持白色。

标题占满剩余宽度，超长时尾部省略；行内日期保持完整。D02 暂定标题 14sp、日期 12sp、行高 52dp，标签 13sp；主体按钮、日期和操作按钮各有独立点击区域。主操作目标高 48dp，窄屏下方框和 `×` 的目标宽度暂为 40dp / 36dp，表翻页为 32dp。T-004 必须在 P60 检查这些窄目标是否易点、是否误触，并在保持单行完整日期的前提下扩大可用目标。桌面空间伸缩优先改变列表高度，首版保持一种布局。

### 2.3 表标签与空态

- D03：每页最多三个表标签，长名在标签内单行省略；当前页边界翻页按钮禁用并保留占位。翻页只展示其他标签，点击标签才切表。翻页后原选中表可能位于另一页，任务列表保持不变。
- D04：切表保留当前子表类型并回到列表顶部；三个子表切换也回到顶部。任务操作返回后保留原表、原子表和仍有效的列表滚动位置；列表缩短时按实际范围收敛。
- D05：有日期／无日期空列表仅显示“点击右上方+添加任务”；已完成空列表仅显示“当前没有已完成任务”。组件与 App 使用相同文案，工具区保持原位。
- 长表名的完整内容通过 App 页面作用域、表管理的重命名页及删除确认查看；组件不增加长按手势。

### 2.4 子表菜单

所有子表保留可点击 `…`。菜单抬头显示“完整表名 / 当前子表”，内容只作用于该子表。

| 子表 | App 轻量页内容 | 返回或进入操作 |
|---|---|---|
| 有日期 | “当前子表暂无可用操作” | 顶部返回回到原入口 |
| 无日期 | 唯一菜单项“修改排序” | 进入当前表的无日期排序页；顶部返回回原入口 |
| 已完成 | “当前子表暂无可用操作” | 顶部返回回到原入口 |

D06 采用可点击说明页承载空菜单，明确按钮有效且暂无操作；退出集中在顶部返回入口。表管理在 App 首页，保持菜单的子表作用域（R57、R62）。

## 3. App 页面与返回路径

### 3.1 页面清单

| 页面 | 进入方式 | 主要内容与退出 |
|---|---|---|
| App 首页 | 启动 App | 工具栏“任务 · 当前表”和“表管理”；下方延续表、子表及任务列表 |
| 添加/详情编辑 | 组件或 App 的 `+`、任务标题 | 所属表、必填标题、选填描述、完整日期、保存；详情另有删除入口 |
| 日期设置 | 编辑页日期字段 | 年月日、可选时分、当前值预览、不设置日期、确认日期 |
| 子表菜单 | 任一 `…` | 作用域、适用菜单项或空态、顶部返回 |
| 修改排序 | 无日期子表菜单 | 当前表、任务序号与标题、上移下移、保存排序 |
| 管理表 | App 首页右上“表管理” | 表名、全部任务数、新建、改名、上移下移、删除 |
| 新建/重命名表 | 管理表 | 完整表名输入、保存 |
| 操作确认 | 方框、日期、`×`、删除表、未保存退出 | 操作对象、结果说明、取消和明确的确认按钮 |

D01／D07：App 首页、编辑、日期、排序、表管理和菜单统一黑底，输入与操作保持可读对比，系统栏采用浅色图标。确认采用深灰居中弹窗以区分黑色页面；组件入口的确认透出原桌面，App 内确认保留原页面。Android 由透明流程窗口和 Dialog 承载，添加、编辑等完整页面仍自行铺满黑底。

### 3.2 添加与编辑

- “有日期”新增：今天的年月日，时分留空；“无日期”新增：不设日期；“已完成”没有 `+`。
- 点任务标题进入可直接编辑的详情，展示完整标题、描述及实际精度的日期。无日期显示“未设置日期”；仅日期显示 `YYYY-MM-DD`，有时分显示 `YYYY-MM-DD HH:mm`。所属表显示“所属表：表名”，保持任务归属固定。
- 标题去除首尾空白后为空时，显示“请填写任务标题”，焦点回到标题。描述允许留空。标题和描述可以多行输入；组件仍只显示单行标题。
- 保存提交整条记录、更新归类和组件。原入口为组件时返回桌面；原入口为 App 时返回原页面。原页面保持原子表，因此任务变化后可能离开当前列表，不自动切换到目标视图。
- 有未保存修改时返回或系统退出，显示“放弃未保存修改？”、“放弃修改 / 继续编辑”；取消保存以外的状态变化。未修改则直接返回。
- 已完成任务可编辑标题、描述和保留日期；保存仍在已完成，恢复时再根据日期归类。完成/恢复通过行内方框执行确认。

D08：App 首页与组件分别记忆自己的表和子表；单个组件记忆最近选中的表、子表和所在标签页，重载时恢复。列表滚动位置仅尽力保持本次交互，不要求重启后恢复。选中表删除后选择删除位置的下一张表，无下一张则选择前一张；至少一张表保证回退有效。网页演示不持久化这些值，Android 版本由 T-004/T-005 实现验证。

### 3.3 日期设置

年月日三列，每列提供填写和 `− / +`。新建依据今天；编辑显示原值；未设日期时进入选择器，以今天作为候选值，按“确认日期”才应用。原始的“未设置日期”在进入前的编辑字段中明确显示。

“设置时分（24 小时制）”默认关闭。开启后显示时、分输入，允许主动输入 `00:00`；只有时或只有分时提示补齐。预览按已有精度显示 `YYYY-MM-DD` 或 `YYYY-MM-DD HH:mm`。

年份按填写值解释，月日变化不推断下一年。日期允许过去值；无效月日和不完整时分在原页提示并保留输入。D09 中加减按钮只改变所在字段，到字段范围边界停止；遇到 2 月 31 日等组合时提示修正，不偷偷改变年份或日期。

“确认日期”将日期暂存到编辑页，整条任务仍需“保存”。日期候选已有修改时返回，先处理放弃/继续，再回到编辑页；没有候选修改则直接返回。点击“不设置日期”时，原来已有日期则先确认取消；确认后只改编辑草稿，最终保存才更新列表。取消确认保留日期输入。对已完成任务取消日期后仍保持已完成。

日期规则沿用 R27–R30、R59–R61、R71–R73；T-004 已验证纯规则和用户操作后刷新，后台刷新精度与跨天实际调度由 T-005 实现、T-006 验收。

### 3.4 修改排序

排序页携带当前表 ID，固定在无日期任务集合。D10 用明确的“上移/下移”逐项调整，首版无需拖拽；首行上移、末行下移禁用。空集合显示空态；少于两项时保存排序禁用，仍可返回。

移动先改草稿，点击“保存排序”持久化整组顺序并刷新组件，按原入口返回。未保存返回时使用相同的“放弃修改 / 继续编辑”。后续新增、取消日期、恢复无日期任务插入最上方，其余已有任务的相对顺序保留。

### 3.5 表管理

首次运行仍按 R65 创建“默认”表；演示预填多张表便于检查翻页。App 首页右上“表管理”是 D11 默认入口。

表管理每行显示表名及全部任务数（包括已完成），提供改名、上移、下移和删除。表顺序使用独立的上移下移按钮，点击即保存并更新组件，边界按钮禁用；这与需要整体保存的任务排序页区分。

新建和改名使用独立表名输入页，允许查看长表名完整内容；“保存”提交。D12 暂定表名必填、去除首尾空白、同名时提示换名；未保存退出沿用放弃提示。新表添加到表顺序末尾，保持当前选中表；改名和排序保留原表 ID 及任务归属。

删除前确认完整表名、任务总数及连同任务删除且无法恢复的后果。仅剩一张表时禁用删除并显示“至少保留一张表”。删除当前表后的选择回退遵循 D08，其他表任务和当前子表类型保持。

## 4. 操作确认与提交点

| 触发 | 标题与结果说明 | 确认按钮 | 确认后 |
|---|---|---|---|
| 未勾选框 | 完成这项任务？显示完整标题；进入已完成最上方 | 确认完成 | 完成时间更新，原日期保留 |
| 已勾选框 | 恢复为未完成？显示完整标题；说明回有日期排序或无日期置顶 | 确认恢复 | 原日期保留，归类到相应视图 |
| 有日期行的日期 | 取消这项任务的日期？显示完整标题；进入无日期最上方 | 取消日期 | 清空年月日和时分，其他任务相对顺序保持 |
| 任务 `×` / 详情删除 | 删除这项任务？显示完整标题；删除后无法恢复 | 删除任务 | 删除记录并刷新，留在原视图 |
| 表删除 | 删除这张表？显示完整表名、含已完成的任务数及不可恢复后果 | 删除表和任务 | 删除表及其任务，更新标签与选中表 |
| 未保存退出 | 放弃未保存修改？说明本次修改未保存 | 放弃修改 | 放弃当前流程的草稿，回到来源 |

普通确认的取消按钮为“取消”，未保存退出则为“继续编辑”；所有取消保留原数据。删除确认按钮用红色，完成、恢复、取消日期使用与深色背景对比的浅色。D13：居中弹窗显示完整对象名和结果，正文可滚动，按钮保持可见；背景沿用原入口，显示范围只有弹窗和背景压暗效果。

操作完成后保留原表和子表，刷新列表并给短提示；取消操作直接返回来源。轻量页从组件进入时，确认或取消后均结束该流程回桌面；从 App 进入则回 App 原页面。详情发起删除时取消返回仍带草稿的详情，确认删除后结束详情。

## 6. 验证与下一步

本次检查范围为浏览器线框的可见布局和样例交互。核对结果与证据由 [T-003 验证记录](design/review.md)承载；后续执行者先看该记录，区分已走查和待实测内容。

T-004 以本稿作为可执行布局输入，优先验证：

1. P60 实际组件区域、逻辑宽高、系统字体缩放、窄按钮命中及长标题/完整日期共存。
2. 固定标签与独立列表滚动、标签翻页和每个行内点击区域，比较 Glance / RemoteViews 能力。
3. 从组件进入 App 的编辑、空菜单、确认和排序；系统返回、保存返回桌面及 App 内返回原页。
4. 键盘弹出、长文本、确认正文滚动及底部按钮可达性。
5. 单组件选择记忆、数据提交后的组件更新、任务顺序持久化以及日期边界刷新。

工程环境与实现取舍继续维护在[技术方向](technical-direction.md)及实际配置；任务状态统一维护在[当前状态](progress.md)，本设计稿不新增执行任务清单。
