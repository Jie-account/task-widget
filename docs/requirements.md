# 首版需求

- 文档版本：v0.11
- 基线日期：2026-10-29
- 状态：核心需求已由用户确认；本次重组沿用原有 R01–R75 编号。
- v0.8 修订：用户在 P60 实测时认可当前 4×4 大小，R64 改为默认该尺寸并支持拖动边框调整大小。
- v0.9 修订：按用户取舍调整首版验收范围，大字体、旋转与草稿恢复、系统日期／时区变化专项验证移入 E15–E17；沿用全部 R 编号和已有业务规则。
- v0.10 修订：按用户反馈统一 App 页面黑色背景，子表菜单保留返回入口，完成／删除等确认直接叠加在原入口上；沿用 R01–R75。
- v0.11 修订：详情所属表仅显示表名，日期按实际精度显示；有日期／无日期空态仅提示添加，已完成空态为“当前没有已完成任务”。
- 入口：[项目说明](../README.md)｜[当前状态与唯一任务清单](progress.md)｜[技术方向](technical-direction.md)

## 1. 目标与范围

| 编号 | 已确认内容 |
|---|---|
| R01 | 开发安卓任务记录软件，首要验证设备为用户实际手机。 |
| R02 | 先形成供本人使用的简易原型，再按实际使用迭代。 |
| R03 | 桌面组件为核心入口，类别可参考滴答清单，使用独立设计。 |
| R04 | 保留合理扩展空间，以首版实际需求决定实现范围。 |
| R63 | 首版按单个桌面组件场景设计。 |
| R64 | 默认采用 P60 实测已认可的 4×4 组件尺寸，支持通过桌面拖动边框调整大小；同一种布局随实际区域伸缩，范围由宿主桌面决定。 |

首版包含表管理、三个任务视图、任务增改删、日期设置、完成与恢复、App 内排序、可调整大小的组件及相应入口。任务跨表移动、多组件独立使用、其他专用组件布局、备份、导入导出和删除恢复留待后续，状态见[扩展方向](future-directions.md)。账号、云同步、提醒和重复任务目前属于候选方向。

## 2. 信息层级与表管理

“表”是一级任务分组；“子表”是同一表内任务的筛选视图。

| 编号 | 已确认内容 |
|---|---|
| R05 | 组件顶部提供类似 Excel 工作表标签的表切换入口，点击切换。 |
| R06 | 表入口下方提供子表标签，点击切换。 |
| R07 | 每个表包含“有日期”“无日期”“已完成”三个子表。 |
| R08 | 表通过三个视图展示任务，每个视图可有多个任务；视图变化沿用同一任务记录。 |
| R51 | 支持表的新增、重命名和排序。 |
| R52 | 首版任务归属固定的表，跨表移动列入后续方向。 |
| R65 | 首次创建“默认”表，允许重命名，始终至少保留一个表。 |
| R66 | 删除表时连同其任务一起删除；操作前显示表名与任务数量并确认。 |

表管理由 App 承载，入口在布局阶段确定。子表菜单的职责见第 7 节。

### 归类规则

| 完成状态 | 日期 | 视图 |
|---|---|---|
| 未完成 | 已设置 | 有日期 |
| 未完成 | 未设置 | 无日期 |
| 已完成 | 设置或未设置 | 已完成 |

三个视图互斥，已完成状态优先。早期“两个子表”已由用户更正为“三个”。

## 4. 三个子表的行为

### 4.1 有日期

| 编号 | 已确认内容 |
|---|---|
| R14 | 展示有日期的未完成任务。 |
| R15 | 日期从早到晚排序，例如昨天 → 今天 → 明天，过期任务保留在前面。 |
| R55 | 同一天先排有时分任务，按时分升序；无时分任务排在该日定时任务之后。 |
| R16 | 日期文字为橙色。 |
| R17 | 已过期任务标题为红色。 |
| R18 | 取消日期后进入“无日期”。 |
| R19 | 点击组件行中的日期，触发取消日期确认。 |

完全相同日期与时分的任务，新创建的在前；完全并列时采用稳定顺序。

### 4.2 无日期

| 编号 | 已确认内容 |
|---|---|
| R20 | 展示无日期的未完成任务。 |
| R21 | 默认新添加的在最上方。 |
| R22 | 支持在 App 内人工调整顺序，组件显示保存后的结果。 |
| R23 | 设置日期后进入“有日期”。 |
| R24 | 行内不显示日期。 |
| R56 | 取消日期的任务插入最上方。 |
| R69 | 新增、取消日期、恢复为未完成的无日期任务均插入最上方，其余任务相对顺序保持。 |

人工顺序持久保存。组件进入排序页的规则见 R57。

### 4.3 已完成

| 编号 | 已确认内容 |
|---|---|
| R25 | 收纳已完成任务，原日期可以有或无。 |
| R26 | 按完成进入顺序倒序，最新完成的在前。 |
| R58 | 允许恢复未完成；保留原日期，恢复后依据是否有日期回到对应视图。 |
| R70 | 组件只显示白色标题与操作按钮，不显示日期；方框为已勾选，点击并确认后恢复。保留删除“×”。 |

详情保留原日期。已完成任务的标题保持白色。

## 5. 日期输入与过期

| 编号 | 已确认内容 |
|---|---|
| R27 | 年份默认今年，允许加减或填写，按用户所选年份解释。 |
| R28 | 月日默认今天，允许加减或填写。 |
| R29 | 时分默认不设置，可主动填写。 |
| R30 | 设置或取消日期后，按日期与完成状态自动更新归类。 |
| R59 | 界面显示当前设置值；新建显示默认值，编辑已有任务显示原值，修改后显示新值。 |
| R60 | 只有年月日的任务，在该日期次日 00:00 起过期。 |
| R61 | 设置时分的任务，超过指定时刻后过期。 |
| R71 | 允许设置过去日期和时刻。 |
| R72 | 时分可一起留空；设置时必须完整，采用 24 小时制 HH:mm，例如 09:30。 |
| R73 | 组件日期显示为 YYYY-MM-DD，例如 2026-10-28。 |

年份依据用户输入，系统不根据所选月日推断下一年。未设置时分与主动设置 00:00 是不同精度，应分别保存。日期控件的具体布局在设计阶段确定。

## 7. 子表菜单

| 编号 | 已确认内容 |
|---|---|
| R62 | 三种子表均保留“...”功能按钮，菜单作用域为当前子表。 |
| R57 | 无日期菜单仅提供“修改排序”，点击进入当前表对应的 App 排序页。 |

有日期和已完成保留按钮，菜单内容暂空；空按钮表现由线框设计给出方案。菜单只承载子表级功能，表管理放在 App 中。早期“修改日期”已确认为“修改排序”的笔误。

菜单页保留顶部返回入口；空菜单说明和“修改排序”之外的退出由返回完成。

## 8. 确认操作与流转

| 编号 | 已确认内容 |
|---|---|
| R43 | 未完成行提供完成方框。 |
| R44 | 标记完成前确认。 |
| R45 | 确认后进入已完成视图最上方。 |
| R46 | 任务行提供删除“×”。 |
| R47 | 删除前确认；首版删除后无恢复入口。 |
| R48 | 点击有日期行的日期触发取消日期。 |
| R49 | 取消日期前确认。 |
| R50 | 确认后进入无日期最上方。 |

恢复未完成前也需要确认（R70）；删除表遵循 R66。确认采用居中弹窗，后方保留桌面组件或原 App 页面；操作对象、结果说明和取消／确认按钮集中在弹窗内。

| 原状态 | 操作 | 结果 |
|---|---|---|
| 无日期、未完成 | 设置日期并保存 | 有日期，按日期排序 |
| 有日期、未完成 | 修改日期并保存 | 保持有日期，按新日期排序 |
| 有日期、未完成 | 确认取消日期 | 无日期最上方 |
| 未完成 | 确认完成 | 已完成最上方 |
| 已完成 | 确认恢复 | 有日期则按日期排序，无日期则置顶 |
| 任意任务 | 确认删除 | 删除 |
| 表 | 确认删除 | 删除表和所属任务，至少保留一个表 |
